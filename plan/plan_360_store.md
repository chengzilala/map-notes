## 三、先实测 MV3 兼容性（关键，先做）

360 Mac 版可能裁剪扩展能力，**不实测不上架**。

1. 打开 360 安全浏览器，地址栏逐个试：`chrome://extensions` → `se://extensions/` → `chrome://myextensions/extensions`。
2. 打开「开发者模式 / 开发人员模式」，出现「加载已解压的扩展程序」。
3. 选择本项目 `extension/` 目录（含 `manifest.json` 的那层，**不要选项目根**）。
4. 打开 `https://www.amap.com/`，逐项验证：
   - [ ] 右下角「留个点」按钮出现
   - [ ] 登录高德后侧栏能列出收藏
   - [ ] 写备注 → 刷新页面 → 备注还在（`chrome.storage.local` 正常）
   - [ ] 搜索、定位后距离排序、1/3/10km 筛选可用
   - [ ] 打开 `https://map.baidu.com/` 后，双源合并显示、落点正确
   - [ ] 控制台无报错

**若 Mac 版没有「加载已解压的扩展程序」**：借一台 Windows 跑第 3–5 步与打包；或先确认扩展在 Chrome / Edge（同为 MV3）表现正常，再到 360 真机复核。

## 四、打包 `.crx`（macOS 实测命令）

前提：`extension/manifest.json` 版本已是 **0.3.0**，并已跑过 `python3 extension/pack.py` 自检。

```bash
cd /Users/Admin/Knowledge/Coding/map-notes

# 首次（没有 .pem）：会同时在 extension/ 上一级生成 extension.crx 与 extension.pem
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --pack-extension="$PWD/extension" \
  --no-message-box --user-data-dir=/tmp/chrome-pack-360

# 之后（复用已有 .pem，应用 ID 不变）
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --pack-extension="$PWD/extension" \
  --pack-extension-key="$PWD/release/map-notes-extension.pem" \
  --no-message-box --user-data-dir=/tmp/chrome-pack-360
```

- 产物默认在 `extension` 的上一级：`extension.crx` / `extension.pem`。
- 把 `.crx` 移到 `release/360-素材/map-notes-v0.3.0.crx`；把 `.pem` 移到仓库外安全位置（如加密盘 / 密码管理器附件），**绝不提交 git、不发聊天**。
- 若首次生成的是 `extension.pem`，先重命名为 `release/map-notes-extension.pem`，再按「之后」的命令重打一次，确认应用 ID 稳定。

> 也可以在 360 浏览器的扩展管理页点「打包扩展程序」，根目录填 `extension/` 的绝对路径，私有密钥一栏首次留空。两种方式产出一致。

## 七、提交步骤

1. 登录 `https://creative.360.com` → 进入扩展 / 应用管理 → 「新建应用」。
2. 上传 `.crx`，等待平台解析出名称、版本、权限（应与 manifest 一致）。
3. 填写名称、短说明、长说明、分类、官网、隐私政策、支持邮箱。
4. 上传图标 192×192、封面 472×296、市场推荐图 1–5 张。
5. 阅读并接受开发人员协议 → 提交审核。
6. 通过后记录扩展 ID 与前台详情页链接到 §九。

> 提交动作由你本人完成；本流程与素材由我准备。

## 八、更新流程（上架后）

1. 递增 `extension/manifest.json` 版本（必须高于线上版本）。
2. `python3 extension/pack.py` 自检 → 重新打 `.crx`（复用 `.pem`）。
3. 创作者中心 → 对应应用 → 「更新扩展」→ 只重传 `.crx`。
4. 若功能 / 隐私说明有变，同步改长说明与隐私页。
5. 提交审核，通过后回填 §九。

**已知平台问题**：后台长说明保存成功（`long_desc` 有值），但公开详情接口的「概述 / moredesc」可能为空。处置：重新提交一次触发详情快照重建；仍为空则向 360 提工单。记录到 §九，不影响审核。

## 十、注意事项

- **先实测再打包**：360 内核对 MV3 支持有限，先确认能加载、能存备注。
- **`.crx` 必须复用 `.pem`**：否则应用 ID 变化，等于重新上架。
- **扩展根目录只指 `extension/`**：指项目根会把 `plan/`、`dev/`、`screenshots/` 全打进 crx。
- **图片尺寸与 Edge 不通用**：360 是 192 / 472×296 / 1120×700；Edge 是 300 / 440×280 / 1400×560。
- 权限最小（仅 `storage` + 三个域名：高德 / 百度 / map.chesterlee.cn）、无远程代码、无分析广告，利于过审。
- 名称、短说明、隐私 URL、支持邮箱与 Edge 保持一致，便于统一维护。
- 不注册账户、不代替你点「提交审核」。
