## 0 先把需求说成 3 件事

| 项 | 内容 |
|---|---|
| **用户目标** | 让第一次听说「留个点」的人在 30 秒内看懂：它把地图收藏变成「能写备注、能按距离找附近」的地方，并且是**只属于自己**的。 |
| **输入 / 输出** | 输入：品牌资产（`brand/v2/*.svg`）、产品截图 / 大图、线上地址。输出：`site/index.html` + `site/assets/{css,js,img}`，可双击打开，也可单独部署到子域。 |
| **成功标准** | ① 首屏 3 秒内出现主张 + 大图 + 一个主按钮；② 全页滚动有 6 处以上可感知动效且不掉帧；③ 手机上单列可读、无横向滚动；④ 全页可见文字控制在 ~200 字内（不含页脚备案）；⑤ 主按钮点击进入 `https://map.chesterlee.cn`。 |

已确认的三项：产品对象＝「留个点」官网；位置＝新目录 `site/`（不动 `web/`）；风格＝深色 + 全屏大图 + 强滚动动效。

**假设（如不认同请指出）**
- 官网对公众开放，但**不含产品功能**，只做介绍与入口；数据与登录仍在应用内。
- 文案中文为主，英文只做装饰性小字。
- 四张大图用本地 SVG 抽象插画（深色地图 / 光点 / 光流），后续可替换为真实界面截图（`site/assets/img/` 同名覆盖即可）。

## 1 主流官网设计分析（我们抄什么、不抄什么）

| 参考站 | 它做对了什么 | 我们取用 |
|---|---|---|
| **Linear** | 深色底 + 一束光打在产品上；滚动时界面像被「推着走」；文字只有短句 | 深色 + 单束渐变光；产品界面随滚动做位移/缩放 |
| **Vercel** | 黑白高对比、超大字排版、网格线做秩序感；每个区块只讲一件事 | 超大字标题；细网格 / 细分割线；一屏一意 |
| **Apple 产品页** | 全屏大图 + 滚动驱动的「分镜」；数字与文案同时渐显 | 全屏大图叙事；滚动进度驱动渐显与数字滚动 |
| **Stripe** | 渐变光晕跟随、卡片微浮起、过渡极短（150–250ms） | 鼠标光晕跟随；卡片 hover 轻位移 |
| **Raycast / Arc** | 强对比配色 + 一两个彩蛋式微交互，克制不喧闹 | 仅在地图撒点与光标上做「小惊喜」 |
| **Awwwards 类获奖站** | 转场、鼠标跟随、夸张排版 | **只借节奏，不借噪音**：不做全屏转场、不做花哨光标拖尾 |

**结论（设计基调）**
- 底色 `#0a0c10`，主色沿用品牌蓝 `#1677ff`，文字 `#e6edf3` / 次要 `#8b949e`，细线 `rgba(255,255,255,.08)`。
- 版式：超大标题（clamp 到 72–120px）+ 一句副标 + 大图；每屏最多 1 个主按钮。
- 动效统一「入场 600–800ms、交互 150–250ms、缓动 `cubic-bezier(.22,1,.36,1)`」。

## 3 详细功能需求

### S1 首屏 Hero
- **需求**：占满 100dvh；背景为一张深色调地图大图（带发光路线/点位感），叠一层从上到下的暗渐变保证文字可读。
- **交互**：
  - 背景随滚动缓慢上移并放大（`translateY(-12%) scale(1.08)`，视差系数 ≤0.3）。
  - 标题按字符/词组依次上浮渐显（总时长 ≤900ms，只播一次）。
  - 主按钮 hover：底色提亮 + 轻微放大 1.02；点击进 `https://map.chesterlee.cn`。
  - 底部一个「向下」提示，滚动 200px 后淡出。
- **参数**：标题 ≤12 字；副标 ≤25 字；CTA 文案 ≤6 字。
- **判定完成**：1440×900 下首屏无横向滚动，文字全部在安全区内，3 秒内完成首屏动画。

### S2 问题 / 一句话价值（已按实现修正）
- **需求**：一整块大字宣言，两行 ≈30 字：「收藏夹里躺着三百个地方，一个都想不起，为什么当初要存下它。」下方一句收束。
- **交互**：文字按字符拆分，**随滚动进度逐个点亮**（未读到的字保持 14% 透明度）；滚动方向反向也能回退。
- **判定完成**：滚到区块中部时大部分文字点亮；关闭动效后整段以 100% 不透明直接可读。

### S3 三个核心能力（本页动效重点）
- **需求**：三个区块，每块 = 一张大图（或界面示意）+ 一行标题 + 一句话。
  1. **写一句就记住**：备注即存，无保存按钮。
  2. **按「离我多远」排**：附近 3 km 从近到远。
  3. **高德 + 百度一起收**：一次同步，两个来源合并。
- **交互**：
  - 区块「粘住」滚动（`position: sticky` + 内部进度），图随进度做 `scale(1.04→1)` 与遮罩揭开，文字在 30% 处渐显。
  - 三张图错位进入（左/右/中），避免整页同一种入场方式。
  - 鼠标在桌面端移动时，图上有 180px 半径的柔光跟随（仅桌面、仅 hover 区块）。
- **边界**：`prefers-reduced-motion` 时取消 sticky 与视差，改为普通渐显；移动端不做 sticky，直接顺序渐显。
- **判定完成**：连续滚动 3 屏无跳帧（Chrome Performance 面板平均 ≥50fps）；关闭动效后内容仍完整可读。

### S4 三步上手
- **需求**：01 同步收藏 → 02 写一句 → 03 找附近；每步 6–10 字。
- **交互**：三步以一条竖线串联，滚动到哪一步哪一步点亮（数字由灰变蓝、圆点发光），已完成步骤保持高亮。
- **判定完成**：滚到页尾时三步全部点亮；「点亮」状态只由滚动位置决定，不依赖鼠标。

### S5 隐私与自持
- **需求**：一句主张「不上传、不分享、不写回地图」，配三个极简图标行（本机存储 / 单一账户 / 可随时清除）。
- **交互**：三行依次从左滑入（间隔 80ms）；图标 hover 时描边变蓝。
- **判定完成**：文案与项目规则一致，不出现「云端同步」「多人协作」等未实现表述。

### S6 页尾 CTA + 页脚
- **需求**：一块居中大 CTA（「现在就去看看」）+ 页脚（版权、ICP 备案号、公安备案号、联系邮箱）。
- **交互**：CTA 按钮持续 6s 一次的呼吸光晕（幅度极小，可用 `prefers-reduced-motion` 关闭）。
- **判定完成**：备案号可点击跳转工信部/公安备案查询；页脚在移动端不溢出。

### S7 导航与滚动进度
- **需求**：顶部固定细导航：左 Logo（`brand/v2/logo-lockup-dark.svg` 或浅色版），右「进入应用」。首屏透明，滚过 80px 后加毛玻璃底与细线。
- **交互**：导航出现/隐藏用 200ms 淡入；右侧 2px 进度条按滚动比例增长。
- **判定完成**：滚动到任意位置导航不遮挡正文；锚点点击平滑滚动（尊重 reduced-motion）。

### S8 移动端适配
- **需求**：≤768px 单列；字号用 clamp 自适应；所有可点区域 ≥44px。
- **交互**：视差与光晕关闭，仅保留渐显；首屏高度用 `100dvh` 防止地址栏跳动。
- **判定完成**：iPhone 尺寸下无横向滚动，动画不卡顿，首屏 CTA 在首屏内可见。

## 4 UI / UX 需求

- **视觉层级**：一屏只允许一个视觉重心（要么大图，要么大字）。
- **文字预算**：全页正文 ≤200 字；每段 ≤2 行；不写长段落、不写功能清单表格。
- **图片规范**：全屏图用 16:9 大图；统一深色调、低饱和、带一束蓝光；本地 SVG（每张 ≤10KB），首屏图 `fetchpriority=high`，其余 `loading=lazy`。
- **字体**：系统字体栈（`-apple-system, "PingFang SC", "Microsoft YaHei", sans-serif`），标题 `font-weight:650`，字距 `-0.02em`。
- **无障碍**：正文对比度 ≥4.5:1；所有动画支持 `prefers-reduced-motion`；图片有 `alt`；键盘可 Tab 到全部按钮并有可见焦点环。
- **性能**：零第三方库、零构建；首屏 JS ≤8KB；Lighthouse 移动端 Performance ≥85、Accessibility ≥90。

## 5 技术实现方案

- **技术栈**：原生 HTML + CSS + JS，零依赖；`site/index.html` 双击可开（相对路径）。
- **文件结构**

```
site/
├── index.html
└── assets/
    ├── css/site.css        # 设计令牌 + 各区块
    ├── js/site.js          # 滚动驱动、渐显、光晕、进度条
    └── img/                # 大图（hero / feature-1..3 / og）
```

- **关键点**
  - 动效用 `IntersectionObserver` 负责「进入视口」，用单个 `scroll` + `requestAnimationFrame` 的节流统一计算视差与进度，避免每个元素各挂一个 scroll 监听。
  - 平滑滚动用 CSS `scroll-behavior: smooth`，不自造惯性滚动（降低复杂度与移动端风险）。
  - 四张大图为本地手绘 SVG（`hero.svg` / `feature-1..3.svg`，各 3–6KB）：不走外链、不依赖生成接口，任何机器都能直接打开；要换图直接同名覆盖即可。
  - 所有动效只在 `transform` / `opacity` 上做，避免布局抖动。
- **不改动**：`web/` 应用本体、`tools/`、部署脚本一律不动；官网独立部署时另配域名或反代路径。

## 8 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 大图体积过大拖慢首屏 | 首屏 3 秒目标不达标 | 四张图都用本地 SVG（≤10KB），其余懒加载；必要时降级为渐变底 + 细网格 |
| 动效过多导致手机掉帧 | 体验变差、像「PPT 卡顿」 | 移动端只保留渐显；sticky 与光晕仅在桌面开启 |
| 首屏与产品真实界面差距过大 | 用户点进去有落差 | 图走「氛围示意」而非伪装成真实截图；文案不承诺未实现能力 |
| 官网与应用部署耦合 | 改动线上应用风险 | 独立 `site/` 目录，先本地双击验收，部署另行确认 |
| 深色 + 低对比导致文字看不清 | 可读性差 | 正文统一 `#e6edf3`，图上一律加暗渐变遮罩；对比度实测 |
