## 0 先回答「能不能像高德一样接」

结论：**能，但不是所有地图都能，且接入方式分三档。**

| 地图 | 官方导出 | 网页版收藏 | 登录方式 | 结论 | 风险 |
|---|---|---|---|---|---|
| 高德 | 无 | 有（`/faves`） | 高德 App 扫码 | **已跑通**（现有 `/ssr/api/cloudSync`） | 低 |
| 百度地图 | 未提供稳定官方导出 | 有「我的收藏」 | 百度账号扫码 | **技术可行，需实测**；收藏接口带签名，直接请求可能 403，要在页面内取数 | 中 |
| 腾讯地图 | 无 | 有「云收藏」，网页/手机同步 | QQ / 微信扫码 | **已实测（2026-11-06）：接口可用（error=0），但网页账号 `total_num=0`，暂无可取数据** | 中 |
| Google Maps | **有**：Takeout → `Maps (your places)/Saved Places.json` | 有 | Google 账号（2FA） | 官方路径本身可行，但**本期决定不接**（不想引入手动导出） | 低 |
| Apple 地图 | 无 | 无网页版 | Apple ID | **确认不做**；只能手动分享「指南」链接，无稳定解析入口 | 高 |
| 花瓣地图 | 无 | 无网页版 | 华为账号 | **确认不做** | — |
| OpenStreetMap | 有开放数据，但无「个人收藏」概念 | — | — | 不适用（只能作为导入格式） | — |

补充三点：

1. **开放平台 API ≠ 收藏接入**：高德/百度/腾讯开放平台的 POI 搜索、地理编码，只能查公共地点，读不到你账号里的收藏。
2. **坐标系不同**：高德/腾讯是 GCJ-02，百度是 BD-09，Google/Apple 是 WGS-84。多源混在一起必须做一次归一，否则会出现几十米到几百米的整体偏移。
3. **风控不同**：高德已实测可低频只读；百度和腾讯的账号风控更严，必须沿用现有原则——只读、每天最多一次、登录由你本人扫码、绝不模拟浏览/点赞。

## 1 项目概述

- **定位**：map-notes 仍然是「一个只给自己用的地点备注 + 附近排序页」，不变成地图聚合器。
- **本次目标**：在现有高德单源基础上，增加**可插拔的多地图源接入**，首批把你在**百度地图**的收藏汇进同一份数据，统一备注、统一定位、统一按距离排；同时把「显示哪个来源」做成**可配置、可记住**的偏好；腾讯保留扩展位。
- **目标用户**：我（单人自用）；不做账号体系，不做分享。
- **当前状态**：只接高德；`favorites.json` 为单源结构（`schemaVersion: 1`，349 个点）；服务器每天 07:30 自动同步；页面无来源概念、无来源筛选。

### 本轮需求三件事

| 项目 | 内容 |
|---|---|
| **用户目标** | 高德 + 百度的收藏都能进到这个页面；默认全部混在一起看，也能只看其中一家；这个选择记住，手机和电脑一致。 |
| **输入 / 输出** | 输入：本人高德、百度账号里的收藏（各自扫码登录一次）+ 页面上的来源选择。输出：一个混合列表（默认全部），可切换「全部 / 高德 / 百度」，选择保存在服务端；卡片上有来源小标签。 |
| **成功标准** | ① 同一次同步能产出高德 + 百度两份数据；② 默认打开是全部混合，列表不重复计数；③ 只看高德 / 只看百度切换即时生效，刷新页面与换设备后仍保持上次选择；④ 高德原有 349 点、备注、搜索、距离全部不回归。 |

## 3 详细功能需求

### M1 多源框架

- **需求**：新增 `tools/sources/`，每个源实现统一接口：`fetch() -> items[]`，由 `tools/sync_all.py` 汇总。
- **行为**：
  - 逐源执行，单源超时/报错只记录该源失败；
  - 每源成功后**原子替换**自己的分片数据，不覆盖其他源；
  - 汇总后写 `web/data/favorites.json`（v2）。
- **判定完成**：禁用任一源（配置关掉）时，其他源照常同步；某源抛异常时，页面仍显示该源上一次数据。
- **边界**：首次同步某源失败不生成空数据，宁可没有该源。

### M2 数据模型 v2

- **结构**（示意）：

```json
{
  "schemaVersion": 2,
  "sources": {
    "amap":   { "syncedAt": "2026-11-04T07:30:00+08:00", "status": "ok", "count": 349 },
    "baidu":  { "syncedAt": null, "status": "not_configured", "count": 0 },
    "qqmap":  { "syncedAt": null, "status": "not_configured", "count": 0 }
  },
  "items": [
    {
      "id": "amap:056968f2...",
      "source": "amap",
      "sourceId": "056968f2...",
      "name": "吴城排工巷",
      "address": "七星桥路",
      "lng": 116.012938,
      "lat": 29.184531,
      "coordSys": "gcj02",
      "rawLng": 116.012938,
      "rawLat": 29.184531,
      "tags": [],
      "createdAt": "2025-06-28T13:32:00+08:00",
      "mergedFrom": []
    }
  ]
}
```

- **约定**：`lng/lat` 永远是页面可直接喂给高德地图的 **GCJ-02**；`rawLng/rawLat` 保留源站原值；`coordSys` 标明原坐标系。
- **兼容**：v1 → v2 迁移时，高德点的 `raw` 与 `lng/lat` 相同（高德本身就是 GCJ-02，**不做预纠偏**）。
- **判定完成**：旧版页面读 v2 不报错；高德 349 个点迁移后坐标一个不差。

### M3 坐标系归一

- **需求**：内置两套转换：`bd09 → gcj02`、`wgs84 → gcj02`（境外点不做偏移）。
- **行为**：只在**入库时**转换一次并落库；页面不再做二次转换。
- **边界**：转换只用于展示对齐；原始值必须保留，便于以后校对/回滚。
- **判定完成**：同一家店在高德与百度各收藏一次，转换后两点直线距离 ≤ 50 m。

### M4 跨源去重

- **需求**：同一地点被多个源收藏时，列表只出现一次，卡片标注「高德 + 百度」。
- **算法（简单优先）**：
  1. 距离 ≤ 50 m 进入候选；
  2. 名称归一（去括号内容、空格、标点）后，相同或互相包含 → 合并；
  3. 不满足则保留为两个点，避免误合并。
- **行为**：合并只在生成展示数据时进行；原始分片数据不删除，可随时拆开。
- **判定完成**：已知重复对（同一店铺）合并成功；相邻但不同的两家店不被误合并。
- **边界**：宁可少合并，不可错合并。

### M5 来源显示与筛选

- **需求**：地图弹卡与列表项显示来源小标签；顶部提供来源筛选；默认「全部」，即**所有来源混在一个列表**里统一排序，不分组、不分段。
- **行为**：
  - 筛选条：`全部 / 高德 / 百度`，只在**已启用**的来源里出现（没有百度数据时不显示百度）；
  - 点某一项 → 只显示该来源；点「全部」→ 混合显示；
  - 合并点（同一地点被多源收藏）只要**包含**所选来源就显示，卡片标注「高德 + 百度」；
  - 筛选与搜索、距离排序**可叠加**，顺序为：来源 → 搜索 → 半径 → 距离排序。
- **默认值**：首次打开（没有保存过偏好）= 全部混合；此后按 M9 记住的选择恢复。
- **判定完成**：349 个高德点 + 百度点混排时，切换筛选不丢点、不重复计数；刷新页面后保持上次筛选。
- **边界**：若保存的筛选源当前没有数据（如只选了百度但百度同步失败），回退到「全部」并在筛选条上标灰该来源，不显示空白列表。

### M6 百度地图接入

- **前置**：你本人在页面里扫码登录百度账号；登录态存独立 profile。
- **行为**：打开百度地图网页收藏页 → 在页面内执行取数 → 取名称/地址/BD-09 坐标/收藏时间 → 转 GCJ-02 → 入库。
- **判定完成**：一次取到 ≥ 10 个真实收藏点，名称与坐标可用；重复跑不产生重复。
- **边界**：
  - 接口带 `ts` 签名，直接 `fetch` 可能 403 → 必须在页面上下文内取数（与高德同一思路）；
  - 页面结构或字段变化时，适配器可单独报错，不影响高德；
  - 不模拟浏览、不点收藏、不写回。

### M7 腾讯地图接入

- **状态**：**阶段 0 已实测（2026-11-06），接口可用但账号无数据，暂不写适配器。**
- **实测结论**：
  - 入口：`map.qq.com` 搜索框下方 `li#FavTab`（「云收藏」），点开后面板 `div#FavViewPanel` 由 `display:none` 变可见。
  - 列表计数：`https://user.map.qq.com/?sk=&action=get&qt=favfilter&data_type=2&fav_type=1&rn=10&pn=0&output=jsonp`
    → `{"detail":{"num":N,"total_num":N},"info":{"error":0,"type":2006}}`
  - 列表/ID：`qt=favpoilist`（无数据时 `detail:{}`）、`qt=favdown`（全部 id）、`qt=favinfo&id=<id>`、`qt=allfavtag`（需登录且 406 时说明缺会话）。
  - 登录态：`https://user.map.qq.com/?action=login&cb=pageInitChk&sk=&trace=<uuid>` → `detail.nick` 为昵称。
  - `sk` 由页面 `getSK()` 生成：优先 cookie `skey`，其次 `lskey`，两者为字符串 `"null"` 时返回空。微信网页登录下两者都是 `"null"`，但会话有效时接口仍返回 `error=0`（`sk` 不是硬门槛）。
  - 错误码：`10001` = 未登录/会话失效；`10005` = 直接访问接口地址（不在页面上下文内）或空 `sk` 直连。
  - 坐标系 GCJ-02，与高德一致，接入无需转换。
  - **取数方式**：必须在页面上下文内取（页面加载时会自己请求 `favpoilist` 与 `favfilter`，可拦截响应），手工直连一律 `10005`。
- **卡点**：实测微信网页账号（昵称「微信用户」）`total_num=0`；QQ 账号两次扫码各等 600 秒均未完成，未能验证。可能原因：App 收藏未同步到网页云收藏，或 App 与网页不是同一账号。
- **重启条件**：当网页版 `map.qq.com` → 云收藏能显示 > 0 条时，再按上面的接口写 `tools/sources/qqmap.py`。
- **判定完成**：一次取到 ≥ 10 个真实收藏点；坐标与高德同点误差 ≤ 50 m。
- **边界**：微信登录可能触发二次验证，失败就提示手动完成，不重试轰炸；收藏只读，不点收藏、不写回。

### M8 多源同步运维

- **需求**：`/admin` 从「一个高德卡」变成「每个源一张卡」：登录状态、上次同步时间、点数、失败原因。
- **行为**：
  - 每天 07:30±30 min 依次同步已启用的源；
  - 某源登录态失效 → 该源标红 + 飞书提醒（文案里写清是哪个源）；
  - 页面顶部新鲜度按「最旧的成功源」计算，或分源展示。
- **判定完成**：模拟一个源登录失效，页面仍可用，且能一眼看出是哪个源需要重新登录。

### M9 显示偏好配置

- **需求**：来源显示不是一次性操作，而是**可配置、可记住**的偏好；存在服务端，手机与电脑打开同一地址看到同一套配置。
- **可配置项**（只做这三项，不扩）：
  1. `enabledSources`：启用哪些来源（多选，至少保留一个）；未启用的来源不出现在筛选条、不参与地图撒点与列表；
  2. `currentFilter`：当前筛选（`all` / `amap` / `baidu`），点筛选条即保存；
  3. `showSourceLabel`：是否显示来源小标签（默认开）。
- **入口**：列表抽屉标题右侧一个「来源设置」小按钮；点开是轻量浮层（不是新页面），勾选即生效、即保存，无「保存」按钮。
- **存储**：`web/data/display.json`，由 `serve.py` 读写：
  - `GET /api/display` → 当前配置；文件不存在时返回默认值（全部启用、`all`、标签开）；
  - `POST /api/display` → 整体覆盖写入（原子写），字段做白名单校验；
  - 不新增账号体系，仍是单人自用的一份配置。
- **边界**：
  - 服务端不可用（直接双击 html / 服务没起）→ 退回浏览器 `localStorage` 暂存，页面顶部沿用现有「备注服务未启动」提示，不新增弹窗；
  - 配置里引用了已不存在的来源（如以后接腾讯又关掉）→ 自动剔除，不报错；
  - 至少启用一个来源；全部取消时自动回到「全部启用」。
- **判定完成**：电脑上把筛选切到「只看百度」，手机刷新后也是「只看百度」；清浏览器缓存不丢配置；删除 `display.json` 后回到「全部混合」。

## 4 UI·UX 需求

- 来源标签：高德（蓝）、百度（红）；后续接腾讯再加绿色；可在来源设置里关掉标签。
- 筛选条：`全部 / 高德 / 百度`，放在搜索条下方，横向一排；只在已启用来源里出现；手机端可横向滑动，按钮 ≥ 44px。
- 来源设置：列表抽屉标题右侧小按钮 → 轻量浮层（勾选来源、显示标签开关）；勾选即保存，无额外确认弹窗。
- 默认视图：**全部混合一个列表**，与现在的使用方式一致；切换成单一来源只是缩小范围，不改变排序规则。
- 合并点卡片：标题下显示「2 个来源」，展开可见各源名称（如百度叫法不同）。
- 失败态：某源失败不影响地图；`/admin` 对应卡片显示「需重新登录」和上次成功时间。
- 不新增学习成本：不打开来源设置时，页面与现在完全一致；来源是附加信息。

## 5 技术实现方案

### 技术栈

- 沿用：Python 3 + Playwright + 本机真实 Chrome（登录/排障时可见窗口；服务器无头 Chromium）+ 纯静态前端。
- 不引入新框架、不引入数据库。

### 文件结构（拟）

```
tools/
├── sources/
│   ├── base.py        # 统一接口、重试与日志
│   ├── amap.py        # 从现有 sync.py 抽出来（行为不变）
│   ├── baidu.py       # 页内取数 + BD-09 → GCJ-02
│   └── qqmap.py       # 预留：后续接腾讯时实现
├── sync_all.py        # 逐源执行 → 合并 → 写 favorites.json v2
├── coord.py           # bd09 → gcj02
└── server_sync.py     # 改为调用 sync_all
```

- profile 分源隔离：`.sync-profile/amap`、`.sync-profile/baidu`、`.sync-profile/qqmap`，全部在 `.gitignore`。
- 前端改动集中在 `web/assets/js/app.js`：读取 v2、来源标签、筛选、来源设置浮层；地图仍用高德 JS API（GCJ-02）。
- 显示偏好：`web/data/display.json`（`serve.py` 原子读写，`data/` 已在忽略列表）；接口 `GET/POST /api/display`；服务端不可用时前端退回 `localStorage`。

### 关键点

1. **先实测再写码**：百度的网络接口、字段、风控必须先登录一次抓一遍，确认可行再动手；腾讯同理，留到扩展时做。
2. **只读、低频**：每源每天最多一次；不模拟浏览、不点赞、不写回。
3. **失败隔离**：一个源坏了，其他源和页面必须照常。
4. **可回滚**：v2 写新文件，保留 v1 备份；出问题一条命令切回。
5. **不预纠偏高德**：高德原始值直接作为 GCJ-02 使用。

## 7 成功标准

1. **高德 + 百度两个源**能在同一次同步里产出数据，且不需要手工复制粘贴。
2. 同一点位跨源对比：转换后坐标偏差 **≤ 50 m**。
3. 跨源重复地点**合并展示**，列表总数不因重复收藏而虚高。
4. 任一源登录失效或接口变更：**其他源与页面照常可用**，并明确提示是哪个源。
5. 现有能力零回归：349 个高德点、备注、搜索、附近排序、手机端全部正常。
6. **显示可配置且能记住**：默认全部混合；只看高德 / 只看百度一键切换；刷新、换设备后保持上次选择；删 `display.json` 回默认。
7. 全流程不写回任何地图、不上传第三方、不记录任何 token/cookie。

## 8 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 百度/腾讯接口签名或页面改版 | 适配器失效 | 适配器隔离 + 失败保留旧数据 + 只维护实际在用的源 |
| 账号触发风控/验证 | 同步中断，甚至影响账号 | 只读、每天≤1 次、手动扫码、不模拟浏览；出验证就停手由你完成 |
| 坐标系转换误差 | 点位偏移 | 标准算法 + 同点抽样校验（≤50 m）；保留原始坐标 |
| 跨源误合并 | 两个不同地点被合成一个 | 50 m 门槛 + 名称相似双条件；宁可少合并 |
| 数据模型迁移出错 | 页面空白 | v2 新文件 + v1 备份 + 原子替换 |
| 显示配置存坏 / 引用了没有的源 | 页面空白或筛选条异常 | 白名单校验 + 自动剔除未知来源 + 至少保留一个源；服务端不可用退回本地存储 |
| 平台条款风险 | 账号或服务受限 | 仅取本人数据、仅本地/自有服务器使用、不分发、不高频 |

## 9 已确认决策

1. 「数据接入」= 读取**我自己账号**的收藏，不是接公共 POI 数据。
2. 首批接入**百度地图**；腾讯地图保留为后续扩展位；Google、Apple 地图、花瓣地图**不做**。
3. 允许页面出现「来源」标识和筛选条。
4. 登录始终由你本人扫码；脚本不托管账号密码。
5. 百度账号你已有，且收藏过地点；首批实测至少能取到 10 个真实点。
6. 本轮范围 = **百度接入 + 来源显示配置**，同一期完成，不拆两期。
7. 「只展示一项」= **按来源筛选**（只看高德 / 只看百度），不是只显示某一条地点。
8. 默认视图 = **全部来源混合成一个列表**，统一排序，不按来源分组。
9. 显示偏好**存服务端**（手机与电脑一致），不满足于只存浏览器。
